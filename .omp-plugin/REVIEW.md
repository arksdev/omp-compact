# Ревью плагина omp-compact

## Состояние после перехода на presenter API

Два цикла ревью 2026-10 (коммиты `87b738a` и `4f2d251`, OMP 18.8.9) проверяли версию 1.x, которая патчила внутренние классы TUI OMP. Все 24 находки тогда закрыты; полный текст остаётся в истории git (`git show v1.4.20:.omp-plugin/REVIEW.md`).

Теперь плагин рисует через публичный transcript presenter OMP 18.17 (`pi.registerTranscriptPresenter`). Код патчей, auto-shake и мост к настройкам OMP удалены, поэтому находки о них больше не относятся к коду:

- P1.1, P1.2 (auto-shake и ошибки сохранения evidence): auto-shake удалён;
- P2.9, P2.12 (раскрытие skill/diagnostics, отменённый session switch): раскрытие рисует OMP, а teardown выполняется только после committed switch;
- R2.3, R2.5 (host YAML, раскрытие advisor): мост к настройкам OMP удалён, раскрытый блок OMP всегда рисует полностью.

Исправления, которые живут в сохранённых модулях, остаются в силе и покрыты тестами: write-evidence привязан к своей source entry (P2.3), пересекающиеся записи одного target отбрасываются (P2.4), quiet commit hash подтверждается только oneline HEAD-log (P2.5), цепочки через `;`/newline остаются обычным Bash (P2.6), `clear` сохраняет сводку коммитов после abort/error (P2.7), цикл `alt+c` сериализуется вместе с сохранением меню (P2.8), display paths хранятся в snapshot своего run (P2.10), создание и удаление пустого файла сохраняются (P2.11), ограниченное чтение config (P3), перенос счётчиков на узкой ширине (P3), R2.1, R2.2, R2.6–R2.10.

## R2.4

R2.4 («raw tool ID не является session-wide identity») закрыт заново. OMP передаёт presenter только `toolCallId` блока, поэтому session ledger хранит под id по записи на run, с hash финальных аргументов, и находит запись блока по `block.args`. Вызовы с одинаковыми id и аргументами в разных run неразличимы: оба рисуются как новейший (`docs/ARCHITECTURE.md`).
